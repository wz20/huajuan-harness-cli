# v0.6.1 发布验收

日期：2026-08-08

版本：Runtime v0.6.1 / Workspace Schema v4

## 本版目标

让用户把完整 ZIP 解压到知识库后，通过父目录启动器完成六步选择，再把最终指令交给 Agent。Agent 必须通过多轮对话确定知识库规则；关键规则未明确、内容未迁移、质量未通过时，不能开始正式入库。

## 已交付能力

| 范围 | 结果 |
|---|---|
| 父目录启动 | 便携包一级父目录作为工作区；已有用户文件可识别，安装包自身不参与扫描 |
| Agent 选择 | Claude Code、Codex、Cursor、Trae、WorkBuddy、通用 Agent；WorkBuddy 交接词和适配文件均验证 |
| 知识门禁 | `KNOWLEDGE_PROFILE`、`STRUCTURE`、`TAXONOMY`、`CONTENT_SCHEMA`、`REFERENCE_RULES`、`LIFECYCLE` 六份契约 |
| READY | 六份契约、Knowledge Lint、Doctor 与用户最终确认全部通过后才可进入 |
| 写入协议 | 未 READY 时 `ingest` 拒绝；READY 后先分类查重、来源保留、格式校验、索引与关系维护 |
| Obsidian | YAML Frontmatter、WikiLink、相对附件、非 Markdown `.huajuan.md` Sidecar |
| 质量检查 | `knowledge scan` 生成 Inventory；`knowledge lint` 检查索引、格式、分类、标签、链接与 Sidecar |
| 自动进化 | 对话和定时采集执行新增、合并、更新、复审、淘汰候选或无需沉淀判断；Proposal 不自动应用，资产不自动删除 |
| Harness 资产 | 7 个系统 Skills、5 个系统 Workflows、系统/用户 Rules、MCP、Memory、Bad Case 与 Evolution 分层 |
| Dashboard | 六视图，新增知识库门禁、六份契约状态、质量指标与可复制命令；保持离线、只读 |
| Doctor | 7 类检查，READY 工作区的知识契约损坏会阻断 |
| 跨平台 ZIP | 中文启动器路径使用标准 UTF-8 标记，避免 Windows / Linux 解压乱码 |

## 边界

- CLI 只做确定性扫描、门禁和质量检查，不替 Agent 决定具体主题、目录、分类和生命周期。
- 向量搜索、云同步、外部模型与数据库不是第一版 READY 的依赖。
- Dashboard 不写工作区、不执行 Shell；所有真实变更仍由 CLI 或受系统协议约束的 Agent 完成。
